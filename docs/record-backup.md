# 기록 백업·복구와 차량 매각 삭제

설정에서 기기 내 공용 문서 폴더를 선택하면 기록 변경 후 백업을 갱신한다. 기본 Android 자동 백업은 계속 꺼져 있다. 서버 전송은 추가하지 않았다.

## 백업 범위와 형식

- 외부 라이브러리 없는 논리 JSON 스냅샷, 형식 식별자 `popolog-records`, 백업 버전 `1`, DB 스키마 `4`.
- 봉투 필드: `format`, `version`, `schema`, `demo`, `createdAt`, `payload`, `sha256`.
- `payload`는 JSON 문자열이며 `tables`, `files`, `folders`, `sequences`를 포함한다. 체크섬은 payload의 UTF-8 바이트에 대한 SHA-256이다. 악의적 재작성의 인증 수단은 아니다.
- `tables`에는 SQLite의 `place`, `trip`, `expense`, `setting`, `ledger`, `anchor`, `sync_item` 표의 모든 열과 ID를 저장한다. INTEGER는 정수, REAL은 숫자, TEXT는 문자열, SQL NULL은 JSON null로 보존한다. 운전자 프로필은 기존과 같이 setting에 포함된다.
- `sequences`는 AUTOINCREMENT의 최댓값이다. 삭제된 비용의 원장 참조 ID보다 낮아지지 않게 복구하여 과거 ID를 재사용하지 않는다.
- 출발·도착 좌표는 확인 후에도 보존한다. 원장 순번·payload·해시와 앵커 영수증을 다시 생성하지 않는다.
- 설치별 `privacy_ack`는 백업에서 제외하고 복구할 때 현재 설치 값을 유지한다. 폴더 권한·실행 중 작업 상태·백업 상태는 별도 SharedPreferences에 저장하며 DB 복구로 바꾸지 않는다.
- `files`는 앱이 생성한 Download/Popolog의 내보내기 파일 주소와 이름이다. `folders`는 백업 폴더 변경 이력을 포함한 관리 대상 공용 폴더 주소다. 주소만으로 재설치 후 접근 권한이 생기지는 않는다.
- 파일은 `popolog-backup-<UUID>.json`, 완료 표시는 같은 이름 뒤 `.done`이다. 완료 표시에는 전체 백업 바이트의 SHA-256을 담는다. 새 파일을 쓰고 다시 읽어 확인한 뒤 완료 표시를 만든다. 그 뒤 최신·직전 정상 백업을 남기고 이전 세대를 정리한다. 임시·미완료 파일도 매각 삭제 대상이다.
- 백업은 최대 64MiB이며 표별 최대 250,000행을 복구한다. 지원하지 않는 형식·버전·모드, 잘못된 표·열·타입·좌표·참조·무결성은 거부한다. NULL은 expense.odo·expense.quantity·sync_item.odo에만 허용한다.

## 사용자 흐름

1. 설정 → 백업 폴더 선택. 기기 로컬의 전용 하위 폴더를 선택한다. 클라우드 제공자·앱 전용 Android 폴더·저장소 루트는 허용하지 않는다.
2. 마지막 성공 시각과 미반영 여부를 확인한다. 변경을 약 2초 간격으로 감지해 갱신하므로 완료 전 강제 종료·제거에는 마지막 변경이 반영되지 않을 수 있다.
3. 앱 제거 시 앱 DB는 지워지지만 완료된 공용 백업은 남는다. 기기 초기화와 사용자 직접 삭제에는 보존을 보장하지 않는다.
4. 재설치 후 설정 → 백업 폴더 선택 후 복구 → 완료된 백업 선택 → 전체 교체 확인. 기존 기록과 자동 병합하지 않는다. 취소·형식 오류·무결성 실패 시 기존 DB를 유지한다.
5. 복구 중 기록·백업·타임스탬프 갱신을 중단하며 DB 교체는 단일 트랜잭션이다. 재설치한 설치의 개인정보 안내 확인 상태와 접근 권한을 유지한다.

백업 파일은 별도 암호화되지 않으며 좌표·이름·금액을 포함한다. 폴더 접근을 허용한 다른 앱이나 사용자가 파일을 읽고 복사할 수 있다. 백업을 보호하려면 기기 잠금과 파일 공유 대상을 관리해야 한다.

## 차량 매각 삭제

- 설정 → 차량 매각·전체 삭제 → 안내 → 정확한 `삭제` 입력. 취소·오타 시 삭제하지 않는다. 데모와 실제 모드 모두 동일한 저장 기능을 사용한다.
- 보존기간이 남아 있어도 전체 삭제하며, 기본·최소 5년 및 연장 기간을 삭제 조건으로 적용하지 않는다. 기간별 정리 자체는 별도 기능이다.
- DB·앱 내부 파일·캐시·앱 전용 외부 파일·알려진 모든 백업 세대·임시 파일·Download/Popolog의 앱 생성 PDF/CSV/검증 JSON을 제거한다. 외부로 공유·복사된 사본은 통제하지 못한다.
- 삭제 완료 전 Download/Popolog 폴더를 직접 선택하여 확인해야 한다. 폴더가 없으면 선택기에서 생성한다. 이전 설치의 파일이나 이전 백업 폴더 접근이 필요하면 삭제 미완료를 표시한다. 삭제 대상 폴더 접근 허용으로 해당 폴더(내보내기는 Download/Popolog)를 다시 선택한 뒤 재시도한다. 앱 생성 파일의 이름·위치를 검사하며 관계없는 파일은 제거하지 않는다.
- 삭제 실패·중단 상태를 설치별로 남겨 재시도한다. 미완료를 전체 삭제 성공으로 표시하지 않는다. 앱 재시작 시 매각 상태에서는 차량 기록을 시작하지 않는다.
- 완료 후에도 기록을 자동 재생성하지 않는다. `새 차량 사용 시작`을 눌러야 다시 기록한다. 기록 중단을 유지하기 위한 내용 없는 매각 완료 상태만 남긴다.
- Pleos 관리자 계정 연동은 아직 없다. 확인 입력은 계정 인증을 대신하지 않는다.

## 기기 확인 범위

문서 선택기가 필요하다. 일부 차량 에뮬레이터는 OPEN_DOCUMENT_TREE에 스텁만 제공하므로 폴더 선택·재설치 복구를 확인할 수 없다. 실제 문서 선택기를 제공하는 기기에서 별도 시연 데이터로 재설치 및 매각 삭제를 확인해야 한다. 기존 사용자 앱이나 데이터를 제거하여 확인하지 않는다.

구체적인 실행 순서·기대 결과·증거·결과표는 [실기기 일괄 확인 체크리스트](device-verification-checklist.md)를 사용한다.

## 백업 암호화 (2026-11-04 구현)

- 백업 파일은 백업마다 난수 데이터 키(AES-256-GCM)로 암호화한다. 데이터 키는 관리자 PIN 유도 키와 복구 코드 유도 키(PBKDF2-SHA256, 210,000회)로 각각 감싸 파일 머리말에 함께 둔다. `.done` 체크섬은 암호화된 파일 전체에 대해 계산한다.
- 머리말에서 평문인 것: 만든 시각, 데모/실제 구분, 내보내기 파일 목록(매각 삭제가 키 없이 목록을 읽기 위함). 운행·비용·좌표·원장 등 기록은 모두 암호문이다.
- 자동 백업에는 PIN 입력이 없으므로 유도 키는 Android Keystore로 감싸 이 설치에만 보관한다. 업무 DB·백업에는 들어가지 않는다.
- PIN 변경·복구 코드로 PIN 재설정 시 새 키가 만들어지고, 새 세대가 기록된 뒤 이전 키로 만든 세대와 기존 평문 백업은 정리된다(앱 관리 폴더 기준).
- 재설치 후 복구: 새 PIN 설정 → `백업에서 복구` → 이 기기의 키로 열리지 않으면 백업을 만들 때의 PIN 또는 복구 코드를 묻는다. 둘 다 잃으면 복구할 수 없다.
- 업데이트 전에 이미 관리자를 설정한 설치는 다음 PIN 인증 때 PIN 키만 생긴다. 복구 코드로 여는 백업은 PIN을 다시 정해 새 복구 코드를 받은 뒤부터 만들어진다.
- 한계: PIN이 숫자 6자리라 백업 파일을 확보한 공격자의 오프라인 대입은 막지 못한다(느린 키 유도로 시간만 늘림). 복구 코드(128비트)로 감싼 키는 대입으로 풀 수 없다. 내보낸 PDF·CSV·검증 JSON은 암호화하지 않는다.
- 아직 에뮬레이터에서 확인하지 않았다(컴파일만 통과).
