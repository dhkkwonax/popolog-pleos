# 보존·제출 확인·운행 단건 삭제

결정 근거: `popolog-team/PROJECT_PROGRESS.md`(task 1.1, 1.3), `PRIVACY_OPERATING_POLICY.md`(task 1.2). 구현 변경: `openspec/changes/enforce-retention-and-trip-deletion`.

## 동작

| 기능 | 위치 | 동작 |
| --- | --- | --- |
| 제출 완료 확인 | 세무 > 제출 확인·보존 | PIN 재확인 후 그해 운행·금액 확정 비용을 한 묶음(`submission`)으로 저장. 확인 시각이 기산점. 방금 저장한 PDF 이름·SHA-256을 선택해 연결 |
| 변경 불가 | 컨트롤러 `canEditTrip/Expense`, 비용 삭제 | 제출에 포함된 운행·비용은 분류·이용자 확인·정정·삭제 거부 |
| 만료일 | `core/Retention.kt` | max(확인일 + 보존 연수, 법정 종료일). 법정 종료일은 관리자가 제출별로 입력, 비면 `미확인` 표시 |
| 보존 연수 | 세무 > 연장 | 5년 이상. 올리면 기존 제출의 연수도 올리기만 한다 |
| 만료 알림 | 홈·세무 배너 | 알리기만 하며 자동 삭제 없음 |
| 운행 단건 삭제 | 운행일지 > 이 운행 삭제 | 제출 미포함 운행만. 영향 안내 → PIN 재확인 → 정확한 `삭제` |
| 원문 파기 | `ChagokDb.purgeTrip` | 한 트랜잭션: 운행 행 삭제, 원장 payload를 `purged|<id>`로 치환(hash 유지), `TRIP_DEL` 줄 추가, WAL 체크포인트·VACUUM, `secure_delete` |
| 검증 표시 | 세무 무결성 카드, `verify.html` | 파기 줄은 저장된 hash를 이어 받고 `원문 파기로 검증 불가`로 표시(변조 판정 아님) |
| 사본 파기 | `RecordBackup.purgeCopies` | 새 백업 세대를 쓰고 이전 세대·다른 백업 폴더의 옛 세대 삭제. 앱이 만든 `Download/Popolog` 파일은 제출 PDF만 남기고 삭제. 실패하면 `삭제 미완료`와 재시도(재시작 때 자동 재시도) |

## 한계 (확정 정책에 남은 후속 설계)

- 제출 PDF에 동반한 원장 JSON처럼 제출자료와 삭제 대상 원문이 섞인 사본은 분리·교체하지 않고 삭제한다. 제출 시점의 원장은 별도 보관이 필요하다.
- 외부로 복사된 사본과 삭제 전 백업 복구로의 재등장은 막지 못한다. 이전 설치가 만든 내보내기 파일은 폴더 접근 없이는 찾지 못한다.
- 저장매체의 물리적 복구 불가능성은 확인하지 않았다. SQLite `secure_delete`·VACUUM은 최선의 정리다.
- 비용 단건 삭제와 비용 메모 파기, 만료 후 수동 정리 절차는 구현하지 않았다.
- 위치·운전자 추정 동의는 자동 운전자 추정과 시트 위치 저장에만 적용된다. 차량 운행 좌표 기록 자체를 막지 않는다.
- 음성 사용 선택은 실제 모드에서 처음 안내 전까지 꺼짐이며, 이미 쓰던 설치는 설정에서 다시 켜야 한다.
- 단위 테스트(`RetentionTest` 포함 43건)와 에뮬레이터(`emulator-5570`, 별도 패키지 `ai.chagok.retentionpreview`·`retentionreal`) 확인을 수행했다. 실차·실제 백업 폴더 선택·사본 파기 통합 확인은 하지 않았다.

## 데모 빌드 백업 시험 경로

에뮬레이터에는 문서 선택기가 없어 데모 빌드에만 고정 폴더 `<공용 저장소>/Popolog-demo-backup`을 백업·복구 폴더로 쓰는 버튼(`데모 고정 폴더로 백업`·`데모 고정 폴더에서 복구`)을 넣었다. `src/demo`의 매니페스트가 `MANAGE_EXTERNAL_STORAGE`를 선언하며 `adb shell appops set --uid <패키지> MANAGE_EXTERNAL_STORAGE allow`로 허용한다. 실제 빌드는 이 코드를 쓰지 않는다.

2026-11-03 확인(에뮬레이터, 별도 패키지 `ai.chagok.retentionpreview`): 고정 폴더 백업 저장 → 운행 삭제 후 이전 백업 세대 삭제(폴더에 1세대만 남음)와 앱이 만든 내보내기 CSV 2건 삭제(`failures=[]`) → 앱 제거·재설치 후 고정 폴더에서 복구 → 파기 상태(`원문 파기로 검증 불가`)와 제출 확인(보존 종료일)이 그대로 복구됨. 사본 파기는 이 앱 소유(`OWNER_PACKAGE_NAME`)의 내보내기 파일만 지우며 다른 설치·앱이 둔 파일은 지우지 않는다.
