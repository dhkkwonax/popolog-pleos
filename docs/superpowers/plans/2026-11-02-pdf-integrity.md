# PDF 파일 무결성 구현 계획

> 실행: 사용자 지시에 따라 현재 세션에서 직접 구현한다.

**Goal:** PDF 안에 RFC 3161 문서 타임스탬프를 넣어 파일 자체의 변경 여부를 확인한다.
**Architecture:** PDFBox Android로 ETSI.RFC3161 /DocTimeStamp를 추가한다. BouncyCastle로 SHA-256 지문·기관 서명을 검증하고, 앱에 배포한 공식 FreeTSA 루트로 인증서 경로를 검증한다. 원장 일일 타임스탬프와 PDF 타임스탬프는 분리한다.
**Spec:** `docs/pdf-integrity-scope.md`

## 범위와 정책

- 생성 PDF는 인증서 검증에 성공한 FreeTSA 토큰만 내장한다. 일일 원장 요청의 Sectigo 대체 경로는 유지한다.
- 외부 요청은 타임스탬프 설정을 따르며 UI 스레드 밖에서 수행한다. 실패 시 미증명 PDF를 사용자에게 명시하고 재시도할 수 있게 한다.
- 타임스탬프 영역 이외의 전체 바이트를 보호하며, 추가 저장·주석·페이지 변경도 미변경으로 통과시키지 않는다.
- 증명 없음, 파일 손상/지문 불일치, 기관 확인 불가를 구분한다. 인증서 폐기 확인·장기 검증 증거는 이번 변경에 포함하지 않고 명시한다.
- 출력물 검증은 제외한다. PDF의 인쇄용 QR과 QR 전용 라이브러리를 제거하고 원장 검증 JSON은 유지한다.
- 관리자 잠금·주행·화면 종료 후에는 결과 표시와 저장을 허용하지 않는다.
- 사용자 지침에 따라 테스트를 추가·실행하지 않는다. 데모·실제 Kotlin 컴파일 및 APK 조립, 코드 검토로 확인하고 실기기 미확인 사항을 기록한다.

## 작업

- [x] 1. PDFBox 의존성(중복 BC 제외), 공식 루트, PDF 증명 생성·검증 구현.
- [x] 2. 미리보기의 비동기 증명·재시도, PDF 파일 선택 검사, 관리자 보호, QR 제거 연결.
- [x] 3. 데모·실제 컴파일 및 패키징 확인, 문서·진행 기록 갱신.

## 검토할 경계

- ByteRange가 파일 전체와 정확히 연결되는지, 제외 구간이 Contents만인지 확인.
- 토큰의 내장 루트를 신뢰 기준으로 사용하지 않을 것.
- UI의 정상 판정이 인증서 폐기 상태까지 확인했다고 주장하지 않을 것.
- 통신 실패·설정 꺼짐·기존 무증명 PDF를 변조로 단정하지 않을 것.
- 기존 사용자 작업 트리 변경을 유지하고 커밋·설치·데이터 삭제를 하지 않을 것.

## 실행 기록

- 사용자 요청이 현재 작업 트리에 쌓인 관리자·백업 구현을 대상으로 하므로 기존 작업 트리에서 변경했다. 기존 변경을 되돌리거나 커밋하지 않았다.
- PDFBox Java getter는 String, setter는 COSName인 API를 확인해 명시적 setFilter/setSubFilter를 사용했다.
- 데모·실제 assembleDebug 성공. PDFBox의 이전 BouncyCastle은 제외했고 duplicate-class 검사와 APK 패키징이 통과했다.
- 두 APK 안의 공식 루트 PEM SHA-256이 공식 공개값과 일치함을 확인했다.
- 별도 읽기 전용 코드 리뷰에서 중요한 지적 없음. 테스트 추가·실행 및 실제 타임스탬프·변조 시나리오 실행은 하지 않았다.
