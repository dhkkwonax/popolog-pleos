# Design

## Context

주행 여부는 현재 `TripRecorder`가 계기판 거리와 주차 브레이크로 판단한다. 광고 전환은 더 즉각적인 차속이 필요하다. `PERF_VEHICLE_SPEED`는 vehicle-app-faq에 CarPropertyManager 읽기/구독 안내가 있으나 권한 값·3rd-party 허용은 미확인이다.

## Goals / Non-Goals

**Goals:** 차속 기반의 단순하고 예측 가능한 광고 화면 전환, 옵트인과 즉시 해제, 기록과 광고의 분리.

**Non-Goals:** 광고 서버·과금, 주행 중 광고 교체, 영상·애니메이션, 도로교통법 적합성 확정.

## Decisions

### 차속 추상화

`VehicleGateway.Listener.onSpeed(kmh: Double?)`를 추가한다(기본 무시). `null`은 "측정 불가"다. 데모는 `SimulatedVehicle`이 주행 중 60, 정차 0을 보낸다. 실제 모드는 `CarPropertySpeedSource`가 리플렉션으로 CarPropertyManager를 시도하고 실패하면 `null`을 보낸다. 값이 없거나 5초 넘게 갱신되지 않으면 광고 모드는 일반 화면을 유지한다(광고를 띄우는 쪽으로 실패하지 않는다).

### 상태 기계 (`AdModePolicy`)

순수 Kotlin 클래스로 시간·속도를 입력받는다. 상태는 `NORMAL`, `AD`.
- NORMAL→AD: 광고 모드 켜짐이며 속도 > 0이 확인될 때 즉시 1회.
- AD→NORMAL: 속도 == 0이 `STOP_HOLD_MS`(4초, 허용 범위 3~5초) 연속 지속될 때만. 이때 다음 광고 이미지로 교체한다.
- AD 동안 이미지는 바뀌지 않는다. 신호 대기 정차가 4초를 넘으면 복귀하며, 다시 출발하면 같은 이미지 대신 다음 이미지로 AD가 된다(복귀 때 교체했으므로).
- 속도 `null`/오래된 값: 현재 상태 유지 후 5초 지나면 NORMAL.
- 광고 모드를 끄면 즉시 NORMAL.

### 소리 광고 빈도

날짜(KST)별 횟수를 설정 키 `ad_voice_day`/`ad_voice_count`에 저장하고 `DAILY_VOICE_LIMIT=2`를 넘기지 않는다. 제안은 정차 상태(NORMAL)일 때만 한다. "다음에"는 해당 제안을 닫고 당일 남은 횟수를 0으로 줄이지 않는다(문서의 "빈도 감소"는 후속 과제).

### 분리

광고 설정·카운터는 `setting` 표의 `ad_` 접두 키만 쓴다. `record()`(해시체인), 세무 리포트, PDF, 백업 스냅샷의 운행·비용 표에 광고 항목을 넣지 않는다. 백업의 설정 포함 여부는 기존 설치별 제외 규칙을 따른다.

### 화면

`AdScreen`은 정지 이미지를 `Canvas`로 그린 단색 배경 + 문구다. 우상단 "광고" 라벨, 하단 작게 "정차하면 기록 화면". 어두운 톤이며 앱 테마(주야간)를 따른다. 터치 동작 없음. 데모 광고 소재는 코드 내 샘플 3종이다.

## Risks / Trade-offs

- 차속 미확인: 사용 불가 시 기능 미동작. 에뮬레이터·실차 확인 후 완료 처리한다.
- 정지 이미지의 주의 분산·법적 회색지대는 미해결이며 문서 리스크 표를 따른다. 적합성은 이 변경이 보증하지 않는다.
- 기존 `isDriving`(계기판 기반)과 광고 전환(차속 기반)이 서로 다른 시점에 바뀔 수 있다. 광고는 `isDriving`에 영향을 주지 않는다.
